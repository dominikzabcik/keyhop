## Learned Workspace Facts

- Keyhop V2 (big-bang 2.0) is being built on the long-lived `v2` branch per the approved plan in `~/.claude/plans/pasted-content-id-7e83-cht-l-bych-prancy-floyd.md`: ~12 weeks, milestones M1 tracker core → M2 UI per `design/keyhop-v2/index.html` → M3 social + live cloud → M4 optimizer/coaching/growth → M5 parity + docs + launch. Cloud changes stay on `main` (backwards compatible, deployed continuously). Key decisions are recorded in `docs/adr/0001`–`0003` and the glossary in `CONTEXT.md`.

- This checkout is Keyhop (`github.com/dominikzabcik/keyhop`): a Swift macOS app (target `Keyhop`), the `keyhop` CLI, and the cloud site at keyhop.app. The directory is named switchr.
- Team day is `/t/<team>/day` (older days use `/day/YYYY-MM-DD`). Machines opt in with `keyhop work add`, `keyhop work on`, and `keyhop work subjects on`. Only commits the person authored count, merge commits are excluded, and each day is rewritten on sync so rebases are not counted twice. Task titles come from commit subjects. The Mac window shows the same day under Teams. The leaderboard and the season rank efficiency (commits per million tokens, past a one-million-token floor) by default, inside plan-based divisions (free, pro, max) that the app reports from its logins' plans; tokens, API value, requests, commits, lines and cache hit stay as metrics, and tiers still follow season tokens. Uploads are verified server-side (requests fit tokens, API value fits a list-price band, cache reads fit tokens). Live sharing is opt-in (`keyhop cloud live on`, Settings → Cloud): today's per-tool totals every ninety seconds to `POST /api/live`, kept with a TTL and swept hourly; a team day marks a person live under three minutes. `keyhop cloud show-data` and Settings → Cloud show every payload before it goes.
- Usage in the window, CLI, JSON, and MCP groups by account, tool, and model. Token totals cover Claude Code, Cursor, Codex, Gemini CLI, OpenCode, and Pi. Copilot, Windsurf, and Codebuff expose limits only, because they do not leave a complete model-token transcript.
- Jev is the Typesafe screen review in CI. Its judgements are reported and do not fail the build.
- A linked account has one lifetime pet, computed from synced daily totals and not stored. Stages are Speck, Hatch (1M tokens), Frame (50M), Bulk (500M), Mass (5B), and Monument (25B). The dominant measured tool sets the markings, the streak sets the pose, and commits set the build. A public profile shares it at `/u/<login>/pet.svg`. The same shapes are painted on the profile, the team page, Overview, the Mac menu, and the iOS season screen. The status icon still shows limits.
- The Mac window is one HTML page served by a loopback server and assembled from `Sources/Keyhop/Dashboard/Page/` (stylesheet, shell, one script file per section); it builds and runs on Linux, so `keyhop dashboard --sample` feeds the window e2e suite and `checks/run.mjs --app` anywhere. The window and keyhop.app share the Keyhop 2.0 world: one warm charcoal ramp, color is state only, paper-on-ink actions, brand blue only in the K mark, the focus ring and the selection; every overlay tint reads from the `--on` ink hue, never a literal white.
- The window is a sidebar app (default 1160x780): every view sits in the sidebar in the open, grouped by `GROUPS` in the page script, with Settings pinned at the bottom. Home is the core screen: the verdict sentence with the one hop button, the pool's runway chart (a day recorded, two days projected from `GET /api/quota`, resets stepping it back up), every login ranked by runway (with its plan and today's figures), and today's figures as a KPI strip. The groups: the core trio Home, Usage and Limits on top with no heading (hopping between logins and the token overview are the product), then the side functions Insights (Coach, Plans, Budgets), Community (Leaderboard, Season, Teams, Profile) and Settings; a view with several sections shows them as tabs and opens on the one last seen. Old links still land (`#overview` → home, `#accounts` → limits). Limits shows every login's last reading, kept in `cli-state.json` across launches; a login whose token older Claude Code or Codex sessions may still hold waits with the session count instead of being refreshed, and a 429 is not asked again before its `Retry-After`. Limits keeps Accounts folded in and the pooled forecast from `GET /api/quota` (also `keyhop forecast` and MCP `keyhop_forecast`, built by `QuotaReport` in `Core/Quota.swift` from the limit samples kept 8 days).
- Plans (`keyhop plans`, window section) prices each login's plan at list against the month's API value and the week's window peaks from the limit samples; Coach (`keyhop coach optimize|compare|yield`, window section) reads cache hit, premium-model share, the heaviest sessions, this month against last, and tokens and API value per commit and per merge from the counted repositories. Both are local; nothing is sent. Coach counts commits with plain `git log` (no `--numstat`, about 14x cheaper) across repositories in parallel, and the window's session keeps the report ten minutes, answers a stale one at once while making the next, and makes the first one a few seconds after the window opens. Cloud boards and days are cached in the page by their exact ask, so only a first look waits, behind skeletons shaped like the view. Teams can post a daily digest to a Slack or Discord incoming webhook (team page, owner only, the hourly cron at the chosen UTC hour); `/u/<login>/wrapped` wraps a year from the daily totals.
- The notch companion (More → Show under the notch) and the menu bar panel are one surface built from `UI/Readout.swift`: a group of limit rows per tool (the login in use, or the roomiest), the read time, and today's line with the window's share greys; the menu adds the verdict with its one action, Refresh and More by the read time, and the logins under a group, and shares the notch's foot (today and Open Keyhop). The menu is not a MenuBarExtra: `UI/MenuPanel.swift` owns the status item and drops a borderless key panel in the notch's bezel (`MenuBezel`: the same black, fillets at the menu bar, the open notch's corners and shadow), because a MenuBarExtra window brings its own material, edge and sizing. The notch lifts at once under the pointer, opens 140 ms later (or on a click), closes 160 ms after it leaves, and a click that closed it stays closed until the pointer comes back; its panel keeps the open size at all times (clear pixels pass clicks to the menu bar, as in boring.notch) and only the shape springs inside it, because resizing the window mid-animation blinks; the hosting view sits inside a plain container so SwiftUI never sizes the panel. Limit notifications use the same words ("5h window, 5% left").
- `native/` is a GPUI Kit (Rust) spike of the Mac window, a client of the same local API (`keyhop dashboard --no-open --json`) the HTML window reads; the Swift core stays the only code that touches logins and usage. `cargo test` and `cargo run -- --sample` in `native/`. The nightly workflow (on main) builds `v2` for macOS on every push to `v2` and bundles `keyhop-native` beside Keyhop.
