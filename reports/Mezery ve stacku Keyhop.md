# Nová úložiště účtů obcházejí přepínač Keyhop

Největší mezera k 3. říjnu 2026 není ve Workers, v D1 ani v notarizaci. Je v tom, že Claude Code, Codex, Copilot CLI a `cursor-agent` čtou přihlášení, které stojí nad souborem nebo Keychain položkou, kterou Keyhop vyměňuje. Přepis `claudeAiOauth`, `~/.codex/auth.json`, `gh auth switch` a `cli-config.json` pořád sedí na dokumentovaný výchozí login předplatného, a přestává být živým účtem, jakmile běží vyšší credential: env token, API klíč, Anthropic profil, keyring, nebo u Cursoru macOS Keychain a v souborovém režimu `~/.cursor/auth.json`. Stejná třída rizika je refresh kvóty za běžící CLI. Claude i Codex varují, že jednorázový refresh token při dvou zapisovatelích zmizí, a obnova je interaktivní login. Na měření přibyly Opus limit a usage credits u Claude, od 15. června 2026 samostatný měsíční pool pro Agent SDK a `claude -p`, a u Copilot CLI jen souhrn při shutdownu sezení. Ze stacku, který keyhop.app už jede, stojí za převzetí tvrdý pád D1 dotazů na Workers Free od 1. září 2026, oprava locator matcherů v `e2e` 0.16.0 a odpověď na `server/discover`. Workflows, Artifacts, MCP Apps, OAuth na stdio a změna jurisdikce D1 k tomuhle request path nepatří.

## Vyšší přihlášení přebíjí soubor, který Keyhop vymění

Claude Code pořád ukládá předplatné do šifrované macOS Keychain, a když zápis Keychain odmítne, spadne do `~/.claude/.credentials.json` s módem `0600`, tedy do stejného souboru, který Linux a Windows používají pořád ([Authentication](https://code.claude.com/docs/en/authentication)). `CLAUDE_CONFIG_DIR` ten soubor i Keychain záznam přesune pod jiný adresář, takže druhý config čte jinou položku. Oficiální pořadí, od nejvyššího, je cloud provider (`CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`), pak `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `apiKeyHelper`, `CLAUDE_CODE_OAUTH_TOKEN`, pak Anthropic profil nebo Workload Identity Federation, a teprve potom subscription OAuth z `/login`. Gateway session sedí mimo ten seznam a přebíjí Bedrock, Vertex i Foundry. V checkoutu Keyhop sahá na službu `Claude Code-credentials` a na `~/.claude.json` v home, a transkripty čte z `~/.claude/projects`. Ten čtenář mine jiný `CLAUDE_CONFIG_DIR` i macOS souborový fallback. Stránka autentizace jméno služby `Claude Code-credentials`, pole `claudeAiOauth` ani `mcpOAuth` nevypisuje. Issue z roku 2026 ten blob ve službě `Claude Code-credentials` pořád ukazují, včetně závodu, kdy souběžný refresh jednorázového tokenu zapíše prázdné `accessToken` a `refreshToken` s `expiresAt: 0` a nechá `subscriptionType` ([Issue 88583](https://github.com/anthropics/claude-code/issues/88583), [Issue 45551](https://github.com/anthropics/claude-code/issues/45551)). Jestli `CLAUDE_CONFIG_DIR` mění jméno služby, account, nebo jen atribut, dokumentace neříká. Keyless Console login od Claude Code v2.1.242 ukládá profil do `~/.config/anthropic` a z claude.ai login odhlásí. `/logout` ten credential smaže a revokuje ([Authentication](https://code.claude.com/docs/en/authentication)). Profil tedy není druhý soubor k tiché výměně.

Codex pořád cachuje přesně jeden login: ChatGPT, API klíč, nebo Codex access token. Cache je plaintext `~/.codex/auth.json`, nebo úložiště operačního systému, podle `cli_auth_credentials_store` (`file`, `keyring`, `auto`, `ephemeral`) ([Authentication](https://developers.openai.com/codex/auth)). Pravidlo „jen ChatGPT sign-in“ pořád popisuje skutečný rozestup metod, a míjí dva uložené loginy, se kterými CLI opravdu běží: API klíč (`codex login --with-api-key`) a access token (`codex login --with-access-token`). Přepis `auth.json` přepne účet, jen když je store `file`. Při `keyring`, `auto` a `ephemeral` soubor není živé tajemství. Commit ve zdroji říká, že úspěšný šifrovaný zápis smaže starý `auth.json` fallback, protože Windows Credential Manager řeže generic credential na 2 560 bajtů. Auth stránka stažená tentýž den sidecar nejmenuje ([Commit 56c97e3](https://github.com/openai/codex/commit/56c97e3b5c8430613afc6d782ab7463bce8df812)). CI průvodce říká, ať refresh endpoint nevolá třetí strana, ať jedna kopie `auth.json` má jednoho zapisovatele, a ať přepis ze starého secretu nezahodí otočené tokeny ([CI/CD auth](https://learn.chatgpt.com/docs/auth/ci-cd-auth)). V checkoutu Keyhop ChatGPT tokeny refresuje sám a píše `last_refresh`. To je stejná třída ztráty jako prázdný Claude blob. `codex logout` uložené credentialy maže. Stránky neříkají, že je revokuje na serveru. `forced_login_method` při neshodě uživatele odhlásí a skončí. Tvar klíčů v `auth.json` oficiální stránka neuvádí. Jmenuje jen `auth_mode: "chatgpt"` a `last_refresh`.

`gh auth switch` pořád mění aktivní účet na hostu a `gh auth token --user` je zdokumentované neinteraktivní čtení. `gh auth logout` cílový účet smaže a při dalších účtech přepne na zbývající ([multiple-accounts.md](https://github.com/cli/cli/blob/trunk/docs/multiple-accounts.md)). Cesta `hosts.yml` v materiálu z roku 2026 není. Copilot CLI už neznamená „to, co používá `gh`“. Pořadí je `COPILOT_GITHUB_TOKEN`, pak `GH_TOKEN`, pak `GITHUB_TOKEN`, pak OAuth z keychainu, a `gh auth token` je nejnižší fallback, jen když není env token ani uložený Copilot token ([Authenticate Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli)). Přepnutí `gh` tedy pořád sedí na editor a na nástroje přes `gh`, a Copilot CLI pohne jen tehdy, když CLI nemá vyšší credential. Druhá cesta je `/user switch` a `copilot login --with-token`. `loggedInUsers` zůstává v `~/.copilot/config.json`. To je největší switching miss mezi těmito třemi: vlastní token Copilot CLI.

Cursor v oficiálních docs pořád dává browser login TypeScript SDK do `~/.cursor/sdk/auth.json` a CLI config do `~/.cursor/cli-config.json` ([TypeScript SDK](https://cursor.com/docs/sdk/typescript), [CLI configuration](https://cursor.com/docs/cli/reference/configuration)). Publikované typy 1.0.27 popisují `StoredSdkCredentials` s `version: 1`, `backendUrl`, `apiKey` a volitelným `apiKeyExpiresAtMs`. Session token se po vyražení klíče zahodí. Výměna toho souboru pokryje výchozí user API key z browser loginu. Nepohne procesem, který klíč už načetl, ani `CURSOR_API_KEY`, service-account klíčem, vlastním `store`, pamětí, ani `store: null`. Service-account klíče jdou do CLI jen jako `CURSOR_API_KEY` a do souboru `sdk/auth.json` je stránka nedává ([Service accounts](https://cursor.com/docs/account/enterprise/service-accounts)). Team Admin klíče `crsr_…` SDK nepřijímá. Od 29. června 2026 umí CLI `AGENT_CLI_CREDENTIAL_STORE=file`. Changelog jméno souboru neříká. Zaměstnanec Cursoru 4. srpna 2026 napsal, že výchozí store je macOS login keychain (služby `cursor-access-token`, `cursor-refresh-token`, `cursor-api-key`, account `cursor-user`) a že ve file módu tokeny skončí v `~/.cursor/auth.json` ([forum](https://forum.cursor.com/t/errsecitemnotfound-couldnt-find-your-saved-login-in-the-macos-keychain/167325)). To je jiná cesta než `~/.cursor/sdk/auth.json` a jiná než `authInfo` v `cli-config.json`. Oficiální schéma `authInfo` neuvádí. `CURSOR_CONFIG_DIR` a na Linuxu `$XDG_CONFIG_HOME/cursor/cli-config.json` jsou zdokumentované polohy, které natvrdo zapsaná cesta `~/.cursor/cli-config.json` nesleduje. Žádný changelog neříká, že editor odešel ze `state.vscdb` nebo přejmenoval `cursorAuth/*`. Deep link `cursor://cursorAuth` se v changelogu CLI ani SDK neobjevuje jako změna. CLI a SDK login v roce 2026 jdou přes web `/loginDeepControl` a `/auth/poll`, tedy jiným předáním než editorový deep link ([login-flow.d.ts @1.0.27](https://cdn.jsdelivr.net/npm/@cursor/sdk@1.0.27/dist/cjs/auth/login-flow.d.ts)). Že deep link na aktuálním buildu pořád funguje, stránky nepotvrzují. Že se rozbil, taky ne.

Právní stránka Anthropic zakazuje třetím stranám nabízet Claude.ai login a routovat requesty přes Free, Pro nebo Max credentialy uživatelů. Pro produkty na Claude chce API klíč přes Console nebo cloud ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). Stránka neříká, jestli lokální přepis souboru, který Keyhop sám na Anthropic neposílá, do té věty spadá. Volání `https://api.anthropic.com/api/oauth/usage` a `https://chatgpt.com/backend-api/wham/usage` v oficiálních stránkách stažených 3. října 2026 není a v ten den se znovu nezkoušelo.

## Čítač pořád sčítá soubory, které kvóta už nepopisuje

Transkripty Claude Code jsou pořád JSONL v `~/.claude/projects/<encoded-cwd>/<session-id>.jsonl`. Slug nahrazuje každý nealfanumerický znak pomlčkou. Od verze kolem 2.1.224 se jméno delší než 200 znaků ořízne a doplní hashem celé cesty, takže čtenář se starým slugem mine adresář ([Manage sessions](https://code.claude.com/docs/en/sessions), [Issue 90221](https://github.com/anthropics/claude-code/issues/90221)). Formát řádku je interní a mezi verzemi se mění. `CLAUDE_CODE_PROJECT_DIR_NAME` (v2.1.234+, jen spolu s `CLAUDE_CONFIG_DIR`) jméno projektu přibije. `CLAUDE_CODE_SKIP_PROMPT_HISTORY` a `claude -p --no-session-persistence` zápis umí potlačit. Výchozí retence je `cleanupPeriodDays` 30 dní. Status line pro předplatitele Claude.ai po první odpovědi nese `five_hour` a `seven_day`, každé s `used_percentage` a `resets_at`. Schéma Opus okno, Sonnet okno ani usage credits nemá ([Status line](https://code.claude.com/docs/en/statusline)). Stránka chyb říká, že session a týdenní limit jsou společné napříč modely a že další limit platí jen pro Opus, takže `/model` po jeho vyčerpání pořád funguje. `/usage-credits` na Pro a Max dokupuje usage ([Errors](https://code.claude.com/docs/en/errors)). Issue z 22. srpna 2026 říká, že při zapnutých kreditech procento plánu není tvrdá zarážka ([Issue 88781](https://github.com/anthropics/claude-code/issues/88781)). **Sto procent na týdenním okně tedy může znamenat čerpání kreditů.** JSON klíče `seven_day_opus` a `seven_day_sonnet` žádná stažená stránka Anthropic nejmenuje. Od 15. června 2026 jde usage Agent SDK a `claude -p` na předplatném z měsíčního Agent SDK kreditu, mimo interaktivní limity, a ty session jsou v pickeru i v `claude --continue` vynechané, zatímco JSONL pořád leží ve stejném stromě ([IAM](https://code.claude.com/docs/en/iam)). Sčítat `usage` na `type: assistant` pořád sedí na zdokumentované místo souboru. Parser se rozbije na release a řádky `claude -p` můžou patřit do jiného poolu než pětihodinové a týdenní okno.

U Codexu je zdokumentovaný transkript `history.jsonl` pod `CODEX_HOME` (výchozí `~/.codex/history.jsonl`). `history.persistence = "none"` ho vypne. Config reference nejmenuje `sessions/`, `archived_sessions/`, `rollout-*.jsonl` ani `token_usage_record` ([Configuration reference](https://developers.openai.com/codex/config-reference)). Checkout počítá `~/.codex/sessions/**/rollout-*.jsonl` a `~/.codex/archived_sessions` a `CODEX_HOME` ignoruje. Dokumentace rollout soubory nepotvrzuje ani neruší. Když pořád existují, jiný `CODEX_HOME` je pro Keyhop neviditelný. Když se tokeny přesunuly jen do `history.jsonl`, čtenář kouká na špatné soubory. To druhé potvrzené není. HTTP kvóta pro třetí stranu na auth stránce není. Nejbližší plocha roku 2026 je lokální JSON-RPC `account/rateLimits/read` na `codex app-server`, v issue s okny `usedPercent`, `windowDurationMins` 300 a 10080, `credits` a `planType`. Jeden report na CLI 0.146.0 dostal jen sedmidenní okno ([Issue 24080](https://github.com/openai/codex/issues/24080), [Issue 20310](https://github.com/openai/codex/issues/20310)). To není veřejný kontrakt. Jestli běžící `codex` znovu čte `auth.json`, resume docs neříkají.

Editor Copilota pořád nemá zdokumentovaný lokální model-token transkript. CLI má `~/.copilot/session-state/<session-id>/events.jsonl`. Oficiální SDK říká, že `assistant.usage` (tokeny, cache, reasoning, premium-request `cost`) je efemérní a při resume se nepřehrává. Trvanlivé čtení je experimentální RPC `session.usage.getMetrics` a `account.getQuota` s `quotaSnapshots` často klíčovanými `premium_interactions`, `chat` a `completions` ([Usage and billing metrics](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing)). Issue 1394 říká, že od začátku března 2026 nese `session.shutdown` v `events.jsonl` `modelMetrics` a `totalPremiumRequests` ([Issue 1394](https://github.com/github/copilot-cli/issues/1394)). Config stránka typy eventů v souboru nevypisuje, takže persistence shutdownu stojí na issue, ne na referenci adresáře. I kdyby se ty řádky počítaly, je to souhrn na konci sezení Copilot CLI, ne přepis každého volání jako u Claude, a editor, cloud agent i efemérní event zůstanou mimo. Po 1. červnu 2026 jsou premium requesty legacy metr pro roční Pro a Pro+, kteří na něm zůstali (Pro 300 za měsíc, Pro+ 1500, reset 1. dne 00:00:00 UTC) ([Requests in GitHub Copilot (legacy)](https://docs.github.com/en/copilot/reference/copilot-billing/request-based-billing-legacy/copilot-requests)). SDK vedle toho ukazuje AI credits v `totalNanoAiu` děleno 1e9. Nástupnický článek pro ostatní plány se v tomhle průchodu nestahoval. UI, které ukáže jen zbytek premium requestů, popisuje špatný pool u účtů, které z legacy billing odešly. Stav „Copilot má limity, ne tokenový přepis“ pro editor pořád platí. Rozšíření dává smysl jen jako částečný součet CLI.

Cursor CSV pořád není v oficiálním seznamu API. `usage-summary` a `export-usage-events-csv` žádná dokumentační stránka nejmenuje. ## Workers, MCP a e2e mění tři konkrétní věci

`compatibility_date` `2026-08-22` v `cloud/wrangler.jsonc` už zapíná Node built-iny, protože od `2026-08-04` jsou `nodejs_compat` a `nodejs_compat_v2` výchozí ([Node.js compatibility default](https://developers.cloudflare.com/changelog/post/2026-08-04-nodejs-compat-default/)). Příznak `nodejs_compat` by byl duplicitní. `no_nodejs_compat` by bylo nové chování. Jediná změna D1, která keyhop.app umí shodit, je vynucení od 1. září 2026: na Workers Free dotaz po denním limitu čtení nebo zápisu řádků spadne až do půlnoci UTC, data zůstanou, přijde e-mail, a binding i REST vrátí text `Your account has exceeded D1's free tier daily row read limit` nebo stejnou větu pro zápis ([D1 free-tier enforcement](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/)). Číselné stropy post neuvádí. Jestli je účet keyhop.app Free nebo Paid, tenhle průzkum nezjistil a `cloud/src` se na ty řetězce neprohledával. Na Paid se post nevztahuje. Než se výpadek syncu bude číst jako bug aplikace, ty dva errory patří buď ošetřit, nebo potvrdit, že nenastávají. Hodinový cron `17 * * * *`, který zametá staré limit řádky, zůstává jeden cron. Nested `migrations_pattern` ve stylu Drizzle by přestal vidět ploché `cloud/migrations/*.sql`, které default `${migrations_dir}/*.sql` bere. `jurisdiction=us` jde nastavit jen při `wrangler d1 create` a později se nepřidá ([D1 changelog](https://developers.cloudflare.com/changelog/product/d1/)). Přestavět databázi `switchr` kvůli US rezidenci, kterou produktové poznámky nepožadují, nemá oporu. Worker Previews od 22. září 2026 izolují Worker a URL, a D1 sdílejí, dokud se nenaváže druhá databáze ([Workers changelog](https://developers.cloudflare.com/changelog/product/workers/)). Config už má `preview_urls: false`. Preview proti živému `switchr` by psalo do produkce. Sessions API a read replikace jsou beta z dubna 2025, jen na bindingu, a bez nich dotazy zůstávají na primárním. Sync na keyhop.app míchá zápisy. Changelog roku 2026 neříká, že malá primární databáze má replikaci zapnout. Artifacts, Workflows a beta `PiHarness` v Durable Objects jsou jiné produkty než jeden cron. `@cloudflare/workers-oauth-provider` v1 z 2. října 2026 umí MCP `2026-07-28` na HTTP. Lokální stdio server Keyhopu tu autorizaci podle specifikace nemá implementovat.

Specifikace `2026-07-28` je vydaná. Jádro je bezstavové, `initialize` není povinný, `server/discover` je volitelný, Tasks, MCP Apps a Enterprise Managed Authorization jsou rozšíření ([2026-07-28 release](https://blog.modelcontextprotocol.io/posts/2026-07-28/)). Autorizace je volitelná. HTTP transport ji má následovat. **STDIO ji následovat nemá a credentialy má brát z prostředí** ([Authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)). Elicitation ve form módu nesmí sbírat hesla, API klíče ani access tokeny. URL mód není způsob, jak se klient autorizuje k serveru. MCP Apps (`io.modelcontextprotocol/ui`, spec 2026-01-26) jsou iframe v chatu a stávající server bez nich funguje dál. Checkoutový `MCPServer` inzeruje `2025-11-25`, umí i `2025-06-18` a `2024-11-05`, a na `server/discover` vrací `-32601`. Přesně to má dual-era klienta vrátit k `initialize`. Klient, který umí jen `2026-07-28` a sondu přeskočí, server neuvidí. Jestli Claude, Cursor nebo Codex pořád padají zpět, se netestovalo. Swift SDK pro `2026-07-28` se neprocházel. Server je ruční JSON-RPC. Jediná protokolová práce, která stojí za to, až nějaký host fallback pustí, je odpovědět na `server/discover` a přijmout metadata `2026-07-28` v těle, a `initialize` nechat pro klienty, které server uvádí dnes. `readOnlyHint`, `destructiveHint: false` a `execution.taskSupport: "forbidden"` k krátkému lokálnímu čtení sedí. Tasks, OAuth, elicitation a Apps k nástrojům `keyhop_status`, `keyhop_usage`, `keyhop_recommendation` a `keyhop_services` nepřidávají plochu, kterou okno a keyhop.app už nemají.

`e2e` 0.16.0 a `@e2e-dev/web` 0.11.2 vyšly 2. října 2026. Lockfile drží 0.15.2 a 0.11.1. `package.json` povoluje `^0.15.2` a `^0.11.1`, takže čistá instalace na 0.16.0 přejde bez změny rozsahu. Oprava, která mění chování, je v `e2e`: `{ checked: false }`, `{ enabled: false }`, `{ visible: false }`, `{ attached: false }` a `{ ignoreCase }` se konečně uplatní. Předtím `toBeChecked({ checked: false })` prošlo na zaškrtnutém boxu a neznámý klíč volby prošel tiše. Teď neznámý klíč padá na `INVALID_ARGUMENT` ([changelog 0.16.0](https://github.com/tester-army/e2e/blob/main/packages/e2e/CHANGELOG.md)). Jestli nějaký spec v repu ty volby používá a spoléhá na to, že se ignorují, po upgradu spadne. To je oprava, kterou changelog popisuje. Hledání těch matcherů v Keyhop specích se nedělalo. Srážka defaultního `tests/` se Swift `Tests/` na case-insensitive disku v 0.16.0 nezmizela. `e2e.config.ts` už `tests` míří na `e2e/window/**/*.e2e.ts` a `e2e/cli/**/*.e2e.ts`, takže upgrade ten override neruší a setrvání na 0.15.2 srážku nevrací. ## Amp, Devin a Cline mají soubor, keyringové CLI ne

Tři sousední nástroje mají vendor stránku, která pojmenovává lokální credential a hodí se na model přepínače, který tokeny neničí loginem naruby. Amp ukládá CLI credentialy do `~/.local/share/amp/secrets.json` a má `amp account switch <name>`. Běžící proces si nechá účet, se kterým nastartoval. `amp logout` maže CLI účty a browser ani nativní aplikaci neodhlásí. `AMP_API_KEY` uložené účty přebije ([Security reference](https://ampcode.com/security), [CLI](https://ampcode.com/docs/cli)). Docs neukazují, jestli víc účtů žije v jednom souboru, ani kde je transkript usage. Devin CLI po `devin auth login` píše token do `credentials.toml` v `$XDG_DATA_HOME/devin/` nebo `~/.local/share/devin/`, token ve výchozím stavu neexpiruje a vendor říká, že soubor lze zkopírovat mezi vlastními stroji. `devin auth logout` ho smaže ([Devin auth](https://docs.devin.ai/cli/enterprise/devin-auth)). Cesta k usage v auth a config stránkách není, takže měření by zůstalo prázdné. Cline drží API klíče a od commitu z 28. dubna 2026 i OAuth tokeny v `~/.cline/data/settings/providers.json`. `secrets.json` je legacy. `CLINE_DATA_DIR` celý data adresář přesune. Session jsou `~/.cline/data/sessions/` jako „session data“, ne jako potvrzený token ledger ([Config](https://docs.cline.bot/getting-started/config)). Výměna tedy musí vzít celý `providers.json`, protože v jednom souboru je víc providerů.

Google Antigravity CLI na lokálním stroji čte token profil z OS keyringu a `/logout` ty profily maže. Jediný zdokumentovaný login mimo keyring je `GEMINI_API_KEY` s `modelProvider: gemini` v `~/.gemini/antigravity-cli/settings.json`, a ten režim účetní session nezakládá ([Install and auth](https://www.antigravity.google/docs/cli/install)). Souborová výměna ve stylu `oauth_creds.json` by šla proti té stránce. Cesta tokenu pro SSH, kterou popisuje třetí strana, v Google docs není. Factory v oficiální CLI referenci jmenuje jen `FACTORY_API_KEY`. `~/.factory/settings.json` jsou preference. Soubory `auth.v2.file` a keychain jsou třetí strana ([Droid CLI reference](https://docs.factory.ai/droid-cli/cli-reference)). Aider bere klíče z env, `.env` nebo `.aider.conf.yml` a účetní soubor nemá. Zed drží klíče v systémovém keychainu. Continue přepíná config soubory, ne přihlášené účty. Augment v tomhle průchodu vendor cestu k loginu nemá. Kiro, Amazon Q Developer CLI a Goose se neprocházely dost na to, aby šly přidat nebo vyloučit.

## Závěr

Rok 2026 na Cloudflare a u Apple je seznam věcí, které tenhle stack nemá přebírat, plus tři úzké adopce: texty D1 Free pádu, matchery `e2e` 0.16.0 a `server/discover` vedle stávajícího `initialize`. Produktový rozdíl je jinde. Každý velký CLI přidal credential, který výměnu dosavadního souboru přežije, a refresh kvůli vykreslení limitu je přesně ten zápis, před kterým Claude i Codex varují, protože otočí jediný refresh token pod běžícím procesem. Další adaptéry, které mají o co se opřít, jsou Amp, Devin CLI a Cline. Antigravity a Factory by zopakovaly Windsurf: cesta z cizího reverse-engineeringu bez vendor stránky. Copilot editor, Windsurf a Codebuff pořád nemají oficiální tokenový deník, takže limity bez přepisu zůstávají poctivý strop, a jediný nový částečný deník je shutdown Copilot CLI.
